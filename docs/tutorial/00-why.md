# 00 · 为什么 Android 上"不依赖链路"很难

> 本篇没有代码。它要解决一个前置问题：**你凭什么觉得这套东西值得拆成这么多层。**

## 场景先钉死

不是"两台手机互相发消息"，而是这三个条件同时成立：

1. 附近（同一房间、同一辆车、同一条船上）
2. 没有可用路由器，或者不希望流量出局域网
3. 要传的东西从几十字节的文字，到几 MB 的图片，到持续的帧流

第 1、2 条排除掉了所有走服务端的方案，第 3 条排除掉了"一次一个包"的方案。

## 候选链路，各自的坑

| 链路 | 传数据能力 | 致命问题 |
|---|---|---|
| 蓝牙 RFCOMM | 有 | 吞吐太低，几 MB 的图片要按分钟算 |
| 蓝牙 BLE | 有 | 单包 20~512 字节，只适合信令 |
| Wi-Fi P2P（Wi-Fi Direct） | 有 | 权限、组主选举、一台设备同时只能在一个组里 |
| 同一局域网 + 手输 IP | 有 | 需要用户知道 IP，还要处理路由器 AP 隔离 |
| 热点 AP | 有 | 只有一端能当 AP，另一端行为受系统策略影响 |
| Nearby Connections | 有 | 依赖 GMS，且 API 只给你"连接"，不给你数据格式 |

结论：**没有一条链路能满足全部三种格式**，而且它们连"发现对方"的方式都不一样。

如果 SDK 直接把 Wi-Fi P2P 写死进去，会发生什么：

- 用户报"我这儿 P2P 权限被拒了" → 整个 SDK 不可用，而不是降级
- 想加一个"同一局域网直连"的调试通道 → 要动核心代码
- 想写测试 → 必须开两台真机

**这就是为什么第一件事是抽链路，而不是写功能。**

## 三层抽象，为什么是这三层

```
ZevHub        ← 发现 / 连接 / 会话（应用只看这一层）
  Session     ← 文字 / 请求 / 大块数据 / 流（四种语义）
    Protocol  ← 帧、ACK、序号、致命错误（只管"一条可靠有序字节通道"）
      ByteTransport ← 纯字节流（TCP、P2P、内存管道……）
```

每一层的**唯一职责**是回答一个问题：

- `ByteTransport`：怎么把字节**可靠、有序**地送过去？（不关心字节是什么）
- `Protocol`：这些字节怎么切成**帧**，出错怎么**整个通道一起死**？
- `Session`：一条通道上怎么同时跑**几十个并发业务**而不串线？
- `ZevHub`：谁在附近、怎么连上、连上之后给你什么？

这四问的答案互不依赖，所以**任何一层的替换都不该让上层改代码**。当前实现的抽象边界在链路**之下**（`ByteTransport` 可换，但发现与组网写死在门面层），`ROADMAP` 末尾有一节说清楚。

## 为什么要自己定二进制格式

能选文本格式（JSON/protobuf）吗?可以，但有三个代价：

1. **帧边界必须由自己定**。TCP 是流，任何格式都要解决"这个包到哪儿结束"。一旦自己解帧，就必须自己写流式解码器（[03 篇](03-streaming-decoder.md)）。
2. **in-band 与 out-of-band 信号混在一起**。取消一条传输、拒绝一个流、报一个致命错误——这些如果塞进 JSON 的字段里，接收方必须先完整解析才能判断"这条消息我还要不要继续读"。
3. **大小上限无法在解码前判断**。36 字节头里有载荷长度，所以"1 MiB 上限"在**读载荷之前**就能拒（`WireDecoder` 就是这么做的）。文本格式通常要读完全文才知道有多大。

反过来，自定格式的代价是**你不能再改**。所以第 02 篇花了一整篇讲"把头冻结下来"。

## 一个必须接受的取舍：致命错误 = 关闭连接

协议层没有"这条消息格式错了，我跳过它继续"这个选项。

原因很实在：一旦某个帧的**长度**不可信，后面所有帧的边界都不可信，你想跳过都跳不了。所以 `ProtocolImpl` 的做法是：校验失败 → 发一个 ERROR 帧告诉对方 → 关闭通道。

代价是：**一个坏帧 = 一条会话死亡**。收益是：不会带着错误状态继续跑，也不会出现"有时能连有时不能"的玄学 bug。这个取舍贯穿整套设计，你后面会反复看到它。

## 本篇的自检

如果你想做的东西满足以下任一条，这套架构就是过度的：

- 只要连一次传一段小文本 → 直接用蓝牙 SPP 或 HTTP
- 只需要"在线设备" → 用服务端 + WebSocket
- 只需要传文件 → 用 `Intent`/`SEND` 或 `MediaStore` 共享

只有当"离线 + 多格式 + 不指定链路"三者都要的时候，这套分层才开始划算。
